Routes taking an integer `:id` parse it with `PanWeb.PathId.to_integer!(id, Schema)` (lib/pan_web/path_id.ex) and raise `Ecto.NoResultsError, queryable: Schema` when the record is missing (`Repo.get!` or `get_... || raise(...)`). Both render the shared "404 Not Found" page (lib/pan_web/templates/error/not_found.html.heex, `PanWeb.ErrorView.title/2` for the tab title). In place since 2026-11-04 for users, podcasts, episodes, personas and all four category routes (#537, #557, #558).

**Why:** the user prefers a plain 404 as "the cleaner way" over a flash + redirect or a custom not-found text with status 200; a non-integer id used to raise `Ecto.Query.CastError`, which phoenix_ecto maps to 400. The user also wanted the error page in standard form ("404 Not Found"), not "This url makes no sense for us."
**How to apply:** use the same pattern for new or touched show routes. Don't use it for slug routes (communities use slugs, #483). Test with `assert_error_sent(404, fn -> get(conn, path) end)` (see test/pan_web/views/error_view_test.exs); in dev the debug page shows instead, see [dev-debug-errors-404](dev-debug-errors-404.md). `ErrorView.title/2` receives `@conn.assigns`, not the template assigns, so it takes the status from the template name.
