The design language lives in DESIGN.md (repo root) — keep it updated when a design decision changes; this file holds the why.

- Origin: DaisyUI's stock dark theme under prefers-color-scheme made macOS dark mode unreadable (#430, eec56b93).
- Final setup (72f057ea): only `latte` (default) and `mocha` (prefersdark) themes, `@plugin "daisyui" { themes: false; }`; no data-theme = follow OS; toggle sun / monitor / moon in the sidebar below the menu sets data-theme on <html> (localStorage `pan_theme`), applied before paint by a nonce'd script in _head.html.heex (CSP). Bootflat palette and old `light` theme removed.
- Colors carry no meaning (user): primary blue, secondary mauve (violet stays rare), accent pink, info sky, success green, warning yellow, error red; every pair AA, Latte light accents take dark text #1e1e2e. base-300 = surface0 (crust looked "muddy"). Light text is Latte #4c4f69 — the user perceives near-black as bold.
- Entity colors: podcast peach, episode teal, persona mauve, user flamingo, recommendation green, category maroon; `--color-ctp-*` = Latte accents darkened to 3:1 for icons, Mocha originals.
- User decisions: no solid color areas except the main button of a section (badges outline, alerts/soft buttons tinted with text in base-content, unlayered CSS rules); panels = one base-100 card, semibold heading + 2px color line (frame around panel/heading and dark heading bar tried and dropped); panels side by side get different purposes ("a followed-podcasts panel shows follows"); no "Podcast"/"Episode" labels in front of entity icons; links text color + underline.
- Icons: Tabler 3.49.0 vendored (priv/icons/tabler), fixed color per icon in PanWeb.Live.Icon `@colors`; podcast = microphone, persona = user-star, user = woman. Category icons/colors in DB (Pan.CategoryIcons fill button). User loved Tabler.
- Third-party widgets: OverType (assets/js/overtype_field.js) gets a "pan" theme object whose colors are our CSS variables (var(--color-base-100) etc.), so it follows the toggle without a listener; its own solar/cave themes ignore ours (2026-10-29, user: "beautiful"). Same approach is worth trying for #445 Podlove.
- Podlove (#445, 643c90ea): player is an iframe → hex tokens per theme in assets/js/podlove_player.js, live switch via store.dispatch PLAYER_SET_THEME; subscribe button iframe reads data-color once → rebuilt on theme change; its popup is in OUR DOM (override with `html #podlove-subscribe-popup …`); iframes without color-scheme get a white backdrop under Mocha → `color-scheme: light` on the iframe; cover/poster from https://panoptikum.social like all thumbnails (dev has no files). Outline buttons: `--color-<c>-strong` for primary/accent/info/warning/success in Latte.
- Pads (9730741d): CodeMirror base theme is light → panTheme in assets/js/pad_editor.js from our CSS vars (gutter, cursor, selection, search panel), user: "perfect". #457 (e34d1152): only main actions filled app-wide.
- QR (#456): Mocha QR in Mocha base on Mocha text scans fine on the user's phone once the code keeps 150px and the quiet zone is padding OUTSIDE (shrinking it inside the box broke scanning).
- Latte surfaces (2026-10-29, after the user found the gray page): page base-200 = Latte base #eff1f5, cards base-100 = white (mantle as page looked gray, pre-theme page was #f5f7fa); Latte QR SVG transparent, tile = var(--color-base-200).
- Gotchas: `<.icon>` collides with an imported `icon/1` (search.ex) → use `icon/2`; some controllers serve admin and public templates; DaisyUI outline badges draw the frame in currentColor; removing Tailwind tokens surfaces `@apply` users only at build time.
- Checking: headless Chrome screenshots of logged-out pages (`google-chrome --headless=new --screenshot=… --user-data-dir=<scratchpad>`, `--blink-settings=preferredColorScheme=0` for dark), crop with `convert`; logged-in pages and real clicks are for the user.
