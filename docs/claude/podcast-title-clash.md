## Design discussion 2026-10-12 (after option 2 was implemented, uncommitted)
User facts:
1. **Format feeds**: some shows publish one feed per format (mp3/aac/ogg/opus, often Podlove). They share episode GUIDs; the old title merge bundled them usefully (e.g. 2 "1337@kultur", 13 Countdown, 402 Geschichtenkapsel: format feeds as alternate feeds, episodes with several enclosures; 840 episodes with ogg/opus + another format). Known ones are alternate feeds, so exact URL matching still finds them; *new* imports of format feeds would become separate podcasts.
2. **Successions ("stealing listeners")**: publisher retires A and redirects A's feed to new show B. Example 38578 "Holding Court" → 34909 "Sixers Talk": since 2019-02 the episode updater copies B's episodes into A (7 years); the unique title only blocked the rename. With option 2 alone the monthly refresh would also give A B's title/description/image (I did that to 38578 on dev only).

Decisions / plan (user agreed to the overall picture; numbering continues at #135):
- **"If in doubt, import twice"** (user): no automatic GUID bundling at import (#128 dropped); duplicates are found and merged afterwards by hand.
- **Step 1 (next):** option 2 + **#129**: metadata refresh doesn't take over the title etc. when the feed URL already belongs to another podcast. Only then commit/deploy option 2.
- **#133 succession check** in the episode updater at the moment of a redirect (`Feed.persist_redirect_target` in Pan.Updater.Podcast, and `itunes:new-feed-url` via `update_with_redirect_target`) — the monthly refresh is too late. User's rule: renamed + episode titles stay = rename; renamed + most titles change = new podcast. Threshold (user: "solid"): ≥50 % of the new feed's episode titles known = rename, continue as today; ≤10 % = succession; in between = for the admin (duplicates page). On succession: A unchanged and **not retired** ("as long as the feed parses we don't retire"), redirect not saved, B's URL into the **feed backlog** once (user: protects against malicious takeovers e.g. via bought domains).
- **#134** "without redirect" case (different show on the same URL): importing a URL that already belongs to a podcast is **refused with an error** naming that podcast; user then deletes the old podcast (good faith) and re-imports, or deletes the backlog entry (malicious). Open question to user: refuse every known-URL import, or only succession ones?
- **#131 duplicates page** (current /admin/podcasts/duplicates only groups identical feed URLs — "poor"): signals a) same feed URL, b) feed URL is another's alternate feed, c) same title + overlapping GUIDs, d) same title + overlapping episode titles/enclosure filenames, e) same title only (info). Successions shown separately (merging them would be wrong).
- **#132 merge B into A**: B's feed + alternates → alternate feeds of A; episodes with matching GUID → move enclosures, else move episode; move/dedupe subscriptions, likes, follows, recommendations, categories, communities/curations, engagements, gigs, chapters (FKs don't cascade); Manticore cleanup; delete B.
