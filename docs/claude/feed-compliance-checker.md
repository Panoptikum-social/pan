Added to [backlog.md](../../backlog.md) 2026-09-01 as "Project #2", follow-on from [parser-extraction-roadmap](parser-extraction-roadmap.md). A public-facing feature that checks a podcast's feed against real standards (RSS 2.0, Apple Podcasts spec, Podcasting 2.0, podcast-standard.org) and reports violations, plus separately (info-level, deferred) Panoptikum's own catalog of real-world tolerances it already silently works around.

**Access model, deliberate:** only checkable for podcasts already in the Panoptikum directory. Rolled out in three phases: **C** (shipped first) any logged-in user; then **A** a user with a claimed persona holding a non-self-proclaimed gig on the podcast; then **B** real podcast claiming (proof of feed control — token in feed, or mail to `itunes:owner`). Only personas can be claimed today; no user-to-podcast ownership link exists yet, so B needs that built first.

**Architecture decision (2026-09-19), resolving the prior open tension:** separate mix project `check-my-feed`. Originally a dev-only path dep gated at runtime via `Code.ensure_loaded?`; since 2026-09-20 it is a normal Hex dep (see status below). It parses the raw feed XML itself using only Quinn/xmerl, deliberately NOT reusing Pan's parser — Pan's parser fixes up bad feeds before parsing (project_xmerl_entity_whackamole, project_cp1252_encoding_fix, etc.), which would hide exactly the violations this tool exists to report. The library takes an XML string and does no fetching itself; Pan re-downloads a fresh copy on every check via `Pan.Parser.Download.get/2` (so the SSRF guard still applies), since the point is often to verify a fix the owner just made.

**v1 shipped 2026-09-19 (commit b5daac72):** `PanWeb.Live.Podcast.CheckFeed` at `/podcasts/:id/check_feed` (backlog.md's 2026-09-19 status note says `/pan/podcasts/:id/check_feed` — likely including a reverse-proxy prefix), linked from a "Check feed" button on the podcast page (only rendered when `CheckFeed.available?()`). Downloads the feed async, calls `CheckMyFeed.check/1`, renders findings grouped by severity (error/warning/info) with rule id + spec link + per-instance detail, plus a "Passed" section and a manual recheck button.

**Modularity, explicit personal goal:** user wants a genuinely separate, independently-testable Elixir module/package for the rule engine — hasn't hand-built a standalone Elixir module in ~8 years and wants that practice back. The library repo is `Panoptikum/check-my-feed`, sibling directory `../check-my-feed` (own git history, not tracked in Pan's memory).

**Status 2026-09-20 — live in prod, tested, works.** `check_my_feed` 0.1.0 is published on Hex (license AGPL-3.0-or-later, source github.com/Panoptikum-social/check-my-feed; the repo is also mirrored at code.informatom.com, private). Chosen over a git dep because the code.informatom.com repo is private and the qa Docker build (`mix deps.get --only qa`, no credentials) and prod deploy couldn't fetch it. Pan uses `{:check_my_feed, "~> 0.1.0"}` in all envs; `available?/0` and the `apply` workaround are gone; the "Check feed" button shows for every logged-in user. A new library release means bumping the version, `mix hex.publish` (needs 2FA/OTP), then updating Pan's requirement/lock.

**Apple rules, resolved 2026-09-20:** user pasted Apple's "A Podcaster's Guide to RSS", the artwork guide and the audio requirements page into `handover.txt`; `lib/check_my_feed/rules/apple.ex` was re-checked. Required tags (language, category, explicit) are now `:error`; media types trimmed to Apple's six (audio/x-m4a, audio/mpeg, video/quicktime, video/mp4, video/x-m4v, application/pdf) plus tolerated ADTS AAC (`audio/aac`/`.aac`, `:info` rule `apple.enclosure.adts`, because the audio page hints it's accepted); new rules for the xmlns:itunes declaration, itunes:type + serial numbering, description (4000 bytes/10,000 chars) and 255-char limits, pubDate, item title/explicit, enclosure extension, transcript type, block/complete. The two-category limit was softened to an `:info` rule (Apple only reads the first category). Only Show Cover and Episode Art come in via RSS; all other Apple artwork placements are Connect uploads, so no rules possible. Pixel size/alpha/dpi/real file type and loudness/bitrate need media downloads, i.e. the "active probing" backlog item. Deliberately skipped: leading/trailing-space check (Apple's own examples have it) and duplicate title/description rules (rss2 already covers them).

**Known rough edges noted 2026-09-19 (backlog.md), not yet fixed:** some feed servers 403 Panoptikum's user agent so the check falsely reports failure (2/12 sampled); a rule with nothing to check on a given feed (e.g. enclosure rule, no episodes) counts as "passed" — arguably should be hidden instead; the library's own test suite prints an unsilenced xmerl fatal log line for its broken-XML test ([dev-background-jobs-disabled](dev-background-jobs-disabled.md)'s sibling concern — check-my-feed doesn't have Pan's `Pan.LoggerFilters`); findings only ever cover a podcast's first feed (`Feed.get_by_podcast_id/1`), not all of them.

**0.2.0 (2026-10-12, #105):** rules with nothing to check return `:not_applicable`; `Report.not_applicable` list; Pan shows them in a collapsed "Not applicable" section (ddfdb383, deployed 2026-10-12). Pan requires `~> 0.2.0`.
