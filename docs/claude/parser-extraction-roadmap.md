Added to [backlog.md](../../backlog.md) 2026-09-01, prompted by the `scrub/1` mixed-content crash fix (commit `cf82e1f2`). User asked whether the feed parser could become its own Elixir package; assessment: `lib/pan/parser/` splits into a DB-free "XML → map" core (analyzer.ex/iterator.ex/helpers.ex/rss_feed.ex's parse steps/my_date_time.ex, ~1,800 LOC) versus a majority that's genuine Panoptikum business logic (persistor.ex + the per-entity persistence modules — Ecto upserts, counters, PubSub). `download.ex` isn't actually DB-free either — its redirect handling calls `Feed.check_for_redirect_loop/3` against the `alternate_feeds` table.

User's priorities, explicit: focus 1 is isolation/testability, focus 2 is reusability, and phase 1 is understood to be no sunk cost toward phase 2 either way.

**Phase 1 (motivated on its own):** move `feed_urls/0` off its stray `Repo.all` call, make Download's redirect-loop check injectable, standardize the output map's keys (currently mixes string/atom keys), add test coverage for Analyzer/Iterator/Helpers (Helpers and Analyzer/Iterator tests done 2026-09-21, see [helpers-tests](helpers-tests.md); the rarer tag aliases are still uncovered).

**Phase 2 (only if reuse elsewhere shows up):** split into its own mix.exs, path/git dep first, Hex.pm publish only with real external interest.
